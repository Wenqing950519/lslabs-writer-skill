# Lint 規則（繁體中文）

初稿完成後使用。每組規則附一條 regex、處理門檻與改法。用編輯器的 regex 搜尋或 ripgrep 都可以。

**門檻的意思：** 多數句型出現一次沒有問題，密集出現才是痕跡。未達門檻的命中不必處理。A 組例外，命中就改。

**範圍：** 除 K 組（破折號、分隔連字號與冒號句式）需一併檢查標題與條列外，其餘組別只掃正文。引文、程式碼、表格結構與 URL 內的命中不處理。

## A. 先否定再肯定的對舉句（命中就改）

作者已確認這類句式是 AI 協作的痕跡。

```regex
(不是|並非|並不是|不只是|不僅是|不僅僅是|不在於|與其說)[^。！？\n]{0,24}(而是|而在於|不如說)
```

```regex
從來不(只)?是|(看似|表面上)[^。！？\n]{0,20}(實則|其實|實際上)|你以為[^。！？\n]{0,24}其實
```

改法：直接寫出肯定的那一半。否定的那一半如果帶有讀者需要的資訊，另寫成一句。

注意：改完再搜一次。常見的失敗是把「不是⋯⋯而是」換成「並非⋯⋯而是」。

## B. 硬升華與硬轉折（命中就檢查）

```regex
這其實是一場|這揭示了|這背後(是|反映)|然而真正的|才正要開始|命運的齒輪|讓人不禁|不禁讓人
```

改法：刪掉旁白，寫出實際發生的事或實際的影響。

## C. 八股起手與總結（命中就改）

```regex
總而言之|綜上所述|總的來說|在當今[^，。\n]{0,12}時代|在這個[^，。\n]{0,12}的時代|值得注意的是|不可否認|毋庸置疑
```

改法：刪除，直接寫內容。全文最後一段如果在重述前文，整段刪除。

## D. 品牌用字（命中就改）

這一組是 LS-Labs 的用字規範，與是否像 AI 無關。

```regex
賦能|重塑|顛覆|全面爆發|必看|前所未有|風口|紅利|降維打擊|站長
```

改法：前九個詞改寫出具體發生了什麼變化；「站長」不符合 LS-Labs 用詞習慣，改為「行銷與內容團隊」「網站團隊」或直接省略主詞。

注意：這些詞出現在文章標題、引述他人或討論該詞本身時不處理。

## E. 空泛的學術包裝（全篇兩次以上才處理）

```regex
結構性的|本質(性|上)的|深層的|系統性的|機制性的
```

檢查法：把這個修飾詞拿掉，句意沒有變淡，就刪除。

## F. 同義反覆（同一段兩次以上才處理）

```regex
換言之|也就是說|更具體地說|換句話說|簡單來說
```

改法：留下說得最清楚的那一句，其餘刪除。

## G. 沒有出處的泛稱（同段沒有具體出處就改）

```regex
有人說|很多人(覺得|認為|說)|大家都(覺得|認為|說)|眾所周知|普遍認為|業界(普遍|都)|網路上(常說|流傳|都說)|專家(指出|認為|表示)|研究(顯示|指出|表明)
```

改法：補上具體出處，或改成自己的主張並標明是觀點。同一段內已經接上具體出處的不處理。

## H. 翻譯腔（全篇三次以上，或連續兩段出現才處理）

```regex
對於[^，。\n]{1,20}(來說|而言)|就[^，。\n]{1,15}而言|在[^，。\n]{1,15}方面
```

```regex
當[^，。\n]{2,30}時，
```

```regex
(?m)^(然而|因此|此外|與此同時|另外|同時)，
```

改法：

- 「對於早期團隊來說，招人最難」改成「早期團隊最難的是招人」。
- 「當⋯⋯時」刪掉「當」與「時」，時間關係會變模糊的保留。
- 段首連接詞移到主語後面，或改用口語的「不過」「所以」。論證需要明確路標的保留。

另外人工檢查：中心名詞前的修飾語超過十五個字，或連續兩個以上的「的」，拆成兩句。

## I. 證據措辭與數字（逐一對照事實清單）

```regex
實測(顯示|發現|結果)|數據(顯示|指出|證明)|研究(證實|證明)|證明了|導致了
```

```regex
\d+(\.\d+)?\s*(%|％|倍|成)
```

處理：

- 每個數字都要能在事實清單找到對應的列，文中要有分母與條件。找不到就刪除。
- 「實測」「數據」「研究」開頭的措辭，只能用在依據類型為實測、統計或一手文件的主張上。推論與觀點改用「我推測」「我認為」。
- 「證明了」「導致了」確認是因果還是相關。只是相關就改成「在這次樣本中觀察到」。

## J. 絕對說法（命中就檢查）

```regex
一定(會|能|要)|絕對|必然|毫無疑問|保證|所有[^，。\n]{0,6}都|唯一的
```

改法：有依據就附上依據，沒有就加上適用範圍。

## K. 破折號、分隔連字號與套路化冒號（破折號原則上改掉；冒號只處理套路與過密堆疊）

破折號與分隔連字號（`xxx - xxx`、`xxx—xxx`、`xxx——xxx`）極容易留下 AI 生成痕跡，原則上都應改掉；**冒號（`：`）本身是中文正常的標點符號，不必見到就刪**，只需處理 AI 套路用法（粗體標籤條列、戲劇化停頓、空泛的「結論／結語：」前綴、單段密集堆疊）。

```regex
——|—|[ \t]-[ \t]
```

```regex
\*\*[^*\n]{1,24}\*\*：|^(?:#{1,6}[ \t]+)?(?:結論|結語|總結)：|(?:結論很簡單|原因有[一二三兩123]|重點是|簡單來說|真相是)：
```

> 若要全面盤點段落裡的冒號密度，可用 `：` 掃描全文，再依下列原則判斷保留或改寫：

適用範圍與改法：

- **破折號與分隔連字號（`——`、`—`、` - `）：** 除非真的必要，否則一律改成逗號、句號，或拆成兩個完整句子（英文專有名詞內部的連字號如 `text-based` 不含空白，以及 Markdown 清單行首的 `- `、表格分隔線 `|---|` 不算）。
- **標題與小標中的冒號：**
  - **自然且可保留：** 正常的「主題／比較對象／實驗編號：問題、副標或切角」寫法（例如「`ChatGPT Ads vs. Google Ads：AI 廣告之爭，誰能掌握消費者的下一次決定？`」「`實驗一：……`」「`研究設計：……`」「`實務示範：……`」），只要前後都有實質資訊，不必硬改成逗號。
  - **應改寫：** 沒有資訊增量的套路前綴（如「`結論：……`」「`結語：……`」），或只為了湊對稱而硬拆兩半的空泛口號標題。
- **條列項目中的冒號：**
  - **應改寫：** 連續使用 `- **標籤**：說明` 或 `1. **動作**：解釋` 的固定模板；改寫成自然連貫的句子（需要凸顯重點時，直接把關鍵字詞自然寫入句中即可，不必加粗標籤再接冒號）。
  - **可保留：** 少數確實屬於「參數／欄位對照」「規格屬性」「時間或資料欄位標註」的項目，以及引述原話、官方專有名詞本身含冒號（如 `Web: multimodal`）。
- **正文句中的冒號：**
  - **可保留：** 偶發的引述前導、舉例帶出、定義與格式標註（時間、比例、來源欄位），或自然承接單一短問句／核心定義。
  - **應改寫：** AI 常見的戲劇化停頓冒號（如「`結論很簡單：……`」「`原因有二：……`」「`這完全算錯了：……`」），或同一段內連續多次用冒號拆句導致讀感碎裂時，改用逗號、句號或自然連接詞串起來。

## L. 結構與段落檢查（人工或審稿時巡檢）

以下項目不靠 regex，在審稿時快速巡檢：

- **自問自答：** 如「結果呢？」「為什麼？因為……」，直接改為陳述句。
- **空泛的三段排比：** 除非三項各有具體且不同的實質內容，否則拆開或合併。
- **先預告再總結：** 開頭先報幕「本文將分為四個部分探討……」、結尾又把前文重述一次，直接刪掉報幕與重述。
- **條列項目套模板：** 避免每個條列都長得像「粗體名詞＋冒號＋解釋」，直接寫成自然的句子。
- **命令式教學與「必做檢查清單」口吻：** 實務建議或排查步驟不要寫成「站長怎麼做」「一份可執行的檢查清單」這類命令／肯定式口吻，改用引導式的檢視角度（例如「遇到這類狀況時，可以先從哪幾個順序核對」）。
- **為寫文章找理由的後設雜訊：** 除非主題本身就是模型評測，否則不要在文章裡解釋「為什麼我要寫這篇懶人包」「我們先問了 AI 發現 AI 回答過時了」來證明文章的價值，直接講主題本身即可。
- **段尾金句化：** 把每段的最後一句抽出來排在一起；如果讀起來像金句集，改掉多數段尾，讓段落停在事實或推論本身。
- **原地打轉的段落：** 逐段看這一段比上一段多推進了什麼；說不出來的就合併或刪除。

## 不要處理的

以下寫法不要當成問題去改：

- 問句與設問。
- 「這意味著」。
- 帶編號的小標題。
- 句子長度相近。不為了節奏改句長。
- 承載證據範圍的限定詞，例如「在本次樣本中」「目前還不能下定論」「可能」「通常」。

## 跨篇檢查

regex 抓不到跨篇的重複。Lint 最後一步是讀 `assets/used-log.md`，確認新稿的開頭類型、收尾方式與比喻沒有和最近五篇重複。
