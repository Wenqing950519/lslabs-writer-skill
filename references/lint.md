# Lint 規則（繁體中文）

第二輪做完文章層級的編輯之後使用。每組規則附一條 regex、處理門檻與改法。用編輯器的 regex 搜尋或 ripgrep 都可以。

**位置：** 這份規則清的是句子。全部零命中，不代表開頭有用、主線清楚、段落有價值；那些判斷在 `references/editorial.md`，要先做。

**門檻的意思：** 多數句型出現一次沒有問題，密集出現才是痕跡。未達門檻的命中不必處理。A 組例外，命中就改。

**方向：** 這份規則只負責把東西刪掉或寫直白，不負責把文章改得更保守。任何一組的改法如果會讓句子多出限定詞、條件或出處說明，先確認不加真的會寫錯事實，否則不加。

**範圍：** 除 K 組（破折號、分隔連字號與冒號句式）需一併檢查標題與條列外，其餘組別只掃正文。引文、程式碼、表格結構與 URL 內的命中不處理。

## A. 先否定再肯定的對舉句（命中就改）

作者已確認這類句式是 AI 協作的痕跡。

```regex
(不是|並非|並不是|不只是|不僅是|不僅僅是|不在於|與其說)[^。！？\n]{0,24}(而是|而在於|不如說)
```

```regex
從來不(只)?是|(看似|表面上)[^。！？\n]{0,20}(實則|其實|實際上)|你以為[^。！？\n]{0,24}其實
```

改法：直接寫出肯定的那一半。否定的那一半如果帶有讀者需要的資訊，另寫成一句。

注意：改完再搜一次。常見的失敗是把「不是⋯⋯而是」換成「並非⋯⋯而是」。

## B. 硬升華與硬轉折（命中就檢查）

```regex
這其實是一場|這揭示了|這背後(是|反映)|然而真正的|才正要開始|命運的齒輪|讓人不禁|不禁讓人
```

改法：刪掉旁白，寫出實際發生的事或實際的影響。

## C. 八股起手與總結（命中就改）

```regex
總而言之|綜上所述|總的來說|在當今[^，。\n]{0,12}時代|在這個[^，。\n]{0,12}的時代|值得注意的是|不可否認|毋庸置疑
```

改法：刪除，直接寫內容。全文最後一段如果在重述前文，整段刪除。

## D. 品牌用字（命中就改）

這一組是 LS-Labs 的用字規範，與是否像 AI 無關。

```regex
賦能|重塑|顛覆|全面爆發|必看|前所未有|風口|紅利|降維打擊|站長
```

改法：前九個詞改寫出具體發生了什麼變化；「站長」不符合 LS-Labs 用詞習慣，改為「行銷與內容團隊」「網站團隊」或直接省略主詞。

注意：這些詞出現在文章標題、引述他人或討論該詞本身時不處理。

## E. 空泛的學術包裝（全篇兩次以上才處理）

```regex
結構性的|本質(性|上)的|深層的|系統性的|機制性的
```

檢查法：把這個修飾詞拿掉，句意沒有變淡，就刪除。

## F. 同義反覆（同一段兩次以上才處理）

```regex
換言之|也就是說|更具體地說|換句話說|簡單來說
```

改法：留下說得最清楚的那一句，其餘刪除。

## G. 借權威的泛稱（後面接數字或研究結論時才處理）

```regex
專家(指出|認為|表示)|研究(顯示|指出|表明)|眾所周知|普遍認為
```

```regex
有人說|很多人(覺得|認為|說)|大家都(覺得|認為|說)|業界(普遍|都)|網路上(常說|流傳|都說)
```

處理：

- 第一組後面接的是具體數字或研究結論，而且全文找不到出處時，補上出處，或直接改成作者自己的判斷（不必加「我認為」，直述即可）。
- 第二組是描述一般印象的口語說法，單獨出現不處理；全篇三次以上才挑掉幾個。
- 不要為了這組規則去補一串來源說明，一句帶過出處就夠。

## H. 翻譯腔（全篇三次以上，或連續兩段出現才處理）

```regex
對於[^，。\n]{1,20}(來說|而言)|就[^，。\n]{1,15}而言|在[^，。\n]{1,15}方面
```

```regex
當[^，。\n]{2,30}時，
```

```regex
(?m)^(然而|因此|此外|與此同時|另外|同時)，
```

改法：

- 「對於早期團隊來說，招人最難」改成「早期團隊最難的是招人」。
- 「當⋯⋯時」刪掉「當」與「時」，時間關係會變模糊的保留。
- 段首連接詞移到主語後面，或改用口語的「不過」「所以」。論證需要明確路標的保留。

另外人工檢查：中心名詞前的修飾語超過十五個字，或連續兩個以上的「的」，拆成兩句。

## I. 證據措辭與數字（只查有沒有寫錯）

```regex
實測(顯示|發現|結果)|數據(顯示|指出|證明)|研究(證實|證明)|證明了|導致了
```

```regex
\d+(\.\d+)?\s*(%|％|倍|成)
```

處理：

- 每個數字都要和素材對得上。對不上就改正，素材裡找不到就刪除或改成質性陳述。
- 分母與測試條件不必跟著每個數字出現。只有少了它讀者會誤解量級時才寫（例如「提升 40%」其實是 3 件變 4 件），研究報告則集中寫在方法說明。
- 「實測」「數據」「研究」開頭的措辭後面要真的有對應的實測、統計或文件。沒有的話拿掉這個開頭，把句子留成作者的直述判斷，不必換成「我推測」「我認為」。
- 「證明了」「導致了」不處理。來源只談相關、作者解讀成因果，是作者的判斷，照留。只有放在引號裡的原話要和來源一致。

## J. 絕對說法（只處理引號內與數字本身）

```regex
一定(會|能|要)|絕對|必然|毫無疑問|保證|所有[^，。\n]{0,6}都|唯一的
```

處理：命中的地方如果在直接引述的引號內，或讓數字本身變得不對（來源是「多數」，寫成「所有」並附上原數字），才改回來。其餘一律不處理：作者的判斷、建議、立場，以及對來源的延伸解讀，都可以說得肯定，不加適用範圍。

## K. 破折號、分隔連字號與套路化冒號（破折號原則上改掉；冒號只處理套路與過密堆疊）

破折號與分隔連字號（`xxx - xxx`、`xxx—xxx`、`xxx——xxx`）極容易留下 AI 生成痕跡，原則上都應改掉；**冒號（`：`）本身是中文正常的標點符號，不必見到就刪**，只需處理 AI 套路用法（粗體標籤條列、戲劇化停頓、空泛的「結論／結語：」前綴、單段密集堆疊）。

```regex
——|—|[ \t]-[ \t]
```

```regex
\*\*[^*\n]{1,24}\*\*：|^(?:#{1,6}[ \t]+)?(?:結論|結語|總結)：|(?:結論很簡單|原因有[一二三兩123]|重點是|簡單來說|真相是)：
```

> 若要全面盤點段落裡的冒號密度，可用 `：` 掃描全文，再依下列原則判斷保留或改寫：

適用範圍與改法：

- **破折號與分隔連字號（`——`、`—`、` - `）：** 除非真的必要，否則一律改成逗號、句號，或拆成兩個完整句子（英文專有名詞內部的連字號如 `text-based` 不含空白，以及 Markdown 清單行首的 `- `、表格分隔線 `|---|` 不算）。
- **標題與小標中的冒號：**
  - **自然且可保留：** 正常的「主題／比較對象／實驗編號：問題、副標或切角」寫法（例如「`ChatGPT Ads vs. Google Ads：AI 廣告之爭，誰能掌握消費者的下一次決定？`」「`實驗一：……`」「`研究設計：……`」「`實務示範：……`」），只要前後都有實質資訊，不必硬改成逗號。
  - **應改寫：** 沒有資訊增量的套路前綴（如「`結論：……`」「`結語：……`」），或只為了湊對稱而硬拆兩半的空泛口號標題。
- **條列項目中的冒號：**
  - **應改寫：** 連續使用 `- **標籤**：說明` 或 `1. **動作**：解釋` 的固定模板；改寫成自然連貫的句子（需要凸顯重點時，直接把關鍵字詞自然寫入句中即可，不必加粗標籤再接冒號）。
  - **可保留：** 少數確實屬於「參數／欄位對照」「規格屬性」「時間或資料欄位標註」的項目，以及引述原話、官方專有名詞本身含冒號（如 `Web: multimodal`）。
- **正文句中的冒號：**
  - **可保留：** 偶發的引述前導、舉例帶出、定義與格式標註（時間、比例、來源欄位），或自然承接單一短問句／核心定義。
  - **應改寫：** AI 常見的戲劇化停頓冒號（如「`結論很簡單：……`」「`原因有二：……`」「`這完全算錯了：……`」），或同一段內連續多次用冒號拆句導致讀感碎裂時，改用逗號、句號或自然連接詞串起來。

## L. 結構與段落檢查（人工或審稿時巡檢）

以下項目不靠 regex，在審稿時快速巡檢：

- **自問自答：** 如「結果呢？」「為什麼？因為……」，直接改為陳述句。
- **空泛的三段排比：** 除非三項各有具體且不同的實質內容，否則拆開或合併。
- **先預告再總結：** 開頭先報幕「本文將分為四個部分探討……」、結尾又把前文重述一次，直接刪掉報幕與重述。
- **條列項目套模板：** 避免每個條列都長得像「粗體名詞＋冒號＋解釋」，直接寫成自然的句子。
- **命令式教學與「必做檢查清單」口吻：** 實務建議或排查步驟不要寫成「站長怎麼做」「一份可執行的檢查清單」這類命令／肯定式口吻，改用引導式的檢視角度（例如「遇到這類狀況時，可以先從哪幾個順序核對」）。
- **為寫文章找理由的後設雜訊：** 除非主題本身就是模型評測，否則不要在文章裡解釋「為什麼我要寫這篇懶人包」「我們先問了 AI 發現 AI 回答過時了」來證明文章的價值，直接講主題本身即可。
- **段尾金句化：** 把每段的最後一句抽出來排在一起；如果讀起來像金句集，改掉多數段尾，讓段落停在事實或推論本身。
- **原地打轉的段落：** 逐段看這一段比上一段多推進了什麼；說不出來的就合併或刪除。
- **吊胃口的開頭與轉場：** 開頭只承諾「後面很重要」卻沒給實質資訊、把關鍵答案刻意留到結尾，或靠「結果呢」「事情還沒完」硬造懸念，改成直接把資訊交出來。
- **小標全是問句：** 編輯時用來排順序的問題鏈留在工作區，小標寫成讀者看得懂的內容。
- **每節同一個模子：** 每節都一樣長、都有定義＋例子＋三點建議＋小結，依內容輕重重新分配篇幅，次要的節縮成一兩句。
- **假經歷：** 「有位客戶告訴我」「上週實測」這類作者沒提供的親身經歷，刪掉或改成明白標示的假設。
- **裝飾性的場景細節：** 與推論無關的時間、衣著、情緒、生活場景，刪掉。
- **同義詞輪替：** 同一個概念為了避免重複而換三種說法，統一成一個。技術詞也不必每個都換成比喻。
- **靠版面提高音量：** 反覆加粗、每句獨立成行，拿掉，讓句子自己站得住。
- **疊加的 CTA：** 文末同時放聯絡、訂閱、下載，只留承接正文的那一個；沒有自然的下一步就不放。把每篇都導向同一段品牌口號的收尾，刪掉。

## M. 防禦性寫作（達門檻就刪減合併）

把判斷層層包起來、反覆聲明限制、預先替假想的質疑者辯護，讀起來像查核報告而不是文章。這一組和 AI 句式一樣要除掉。

保留語氣疊加（同一句兩個以上，或同一段三個以上才處理）：

```regex
可能|或許|也許|似乎|大概|某種程度上|在一定程度上|一定程度|不一定|未必|傾向於
```

限制與免責聲明（同一個意思全篇出現兩次以上，第二次起刪除）：

```regex
在(本|這)次(樣本|觀測|測試|實驗)中|單(一|次)(觀測|案例|經驗|樣本)|樣本(數)?(有限|不大|很小|偏小)|(目前|現階段)(還)?(不能|無法|難以)(下定論|斷言|確定)|有待(進一步)?(驗證|觀察|研究)|不代表|不能(直接)?(推論|類推|套用)|僅供參考|需要(特別)?(注意|說明|強調)的是|必須(先)?(說明|強調|提醒)|嚴格來說|保守(地說|估計)|就(我|我們)(目前)?(所知|觀察)|以上(僅|只)(是|為)
```

觀點前綴（全篇三次以上才處理）：

```regex
我(們)?(認為|推測|猜測|傾向認為|的看法是)|個人(認為|覺得|看法)|(這|以下)(只|僅)是(我的)?(推論|推測|觀點|看法)
```

改法：

- **一句只留一個保留詞，能不留就不留。**「這或許在某種程度上可能影響排名」改成「這會影響排名」；作者真的沒把握時，留一個「可能」。
- **同一個限制全篇只講一次，** 放在它真正影響讀者判斷的地方，其餘刪除。開頭不要先交代限制與免責，文末不要再重述一次。
- **觀點直接講。** 整篇文章本來就是作者的判斷，不必每句掛「我認為」。第一人稱留給真的在講個人經驗與立場的地方。
- **刪掉預先辯護。**「當然，也有人會說⋯⋯」「這並不是說⋯⋯」這類回應假想質疑的句子，如果對方的論點文中沒有實際出現，整句刪除。
- **數字後面不拖尾巴。**「提升 37%（但僅限該測試集、單一平台、且未經重現）」這種括號式保留，併成一句必要的說明，或移到方法說明。

不處理的情況：

- 引述他人原話裡的保留語氣。
- 作者真的不確定、而且這份不確定本身就是文章要傳達的訊息。
- 研究報告的方法與限制章節。

## 不要處理的

以下寫法不要當成問題去改：

- 問句與設問。
- 「這意味著」。
- 帶編號的小標題。
- 句子長度相近。句長只因語意需要而調整，不為了模擬真人隨機變換長短。
- 已經被具體內容說明過的抽象詞。
- 肯定、直接的判斷句。不要為了「嚴謹」替它補限定詞、適用範圍或出處說明。

## 跨篇檢查

regex 抓不到跨篇的重複。Lint 最後一步是讀 `assets/used-log.md`：

- 比喻不論多久以前用過，都不重用。
- 切角、主要例子與敘事路線，有沒有和近幾篇走同一條路，把同一個結論再鋪陳一次。有的話換例子或換推進方式。
- 開頭類型、收尾方式相同不算問題。新聞連續從事件開場很自然，不為了形式差異另造生硬的開場。
